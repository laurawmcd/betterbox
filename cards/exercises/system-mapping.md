# System mapping

A system map shows how people, information and decisions move around, and what happens when they arrive. It is not a technical architecture diagram. Start with your most important user and draw how the project will cause change: how a text alert might alter behaviour, or how a new database could get people the help they need. Stick figures and lots of arrows work well.

**Time:** 30 minutes

## How to run it

1. Ask the group to help you draw what happens now. What information is collected, by whom, and where does it go? What are the challenges?
2. Show how information moves from one actor to another, through which channel, and what happens when it arrives.
3. Use the drawing to draw out a discussion of how people make decisions, and what their goals and plans are.
4. Run it in small groups and discuss in plenary, or build it in plenary. If you build it in plenary, start it yourself so it develops correctly, then invite others to take the pen.

## Tips

- Avoid maps that only show information being passed on. A useful map also shows what people do with it in the real world.
- Draw the current system first, then draw how the new one will change it.
